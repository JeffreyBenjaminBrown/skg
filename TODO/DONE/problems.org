* The pacer recorded its session's start time from the wrong process (2026-11-22; fixed 2026-11-22)
  In 'session' ('tools/team/pacer.sh'), the subshell that runs a
  session writes 'running-session' with
  'echo "$BASHPID $(proc_field "$BASHPID" 20) $stamp"'. The second
  '$BASHPID' is inside '$( )', so it is the command substitution's
  own pid: the start time recorded is that short-lived child's, not
  the subshell's. Both usually start in the same clock tick (1/100 s),
  so 'other_pacer' matches them; under load they do not, and then a
  session whose pacer was killed no longer keeps a new pacer from
  starting (ONE PACER in the script's header), so two sessions can
  run at once. Seen in 'tools/team/test_pacer.py' with three busy
  loops sharing its core: the new pacer started a second session
  instead of refusing, and the test timed out; it is likely why that
  test timed out twice while three suites ran at once. The fix is to
  name the subshell's pid once, outside the substitution
  ('me=$BASHPID; echo "$me $(proc_field "$me" 20) $stamp"').
  Fixed so, at the coordinator's word. A running 'pacer.sh run' keeps
  the old text until it is restarted.

* A redraw the user did not ask for undoes the folds changed since the last save (2026-11-13; fixed 2026-11-13)
  A view's fold state reaches the server only as the 'folded' and
  'bodyFolded' atoms of a save. A rerender after another writer's
  change ('rerender-view') or a save's collateral redraw of another
  view draws the folds of that view's last save, so any headline the
  user folded or unfolded since then reverts. Seen live on a scratch
  server, Emacs client: a headline folded after opening the view was
  unfolded by the redraw that followed a '.skg' change on disk.
  Fixed in the clients: before such a redraw replaces the buffer,
  each headline's fold state is recorded by viewnode ID, and decides
  the fold atoms of the new text, a headline's 'folded' by its new
  parent's state and its 'bodyFolded' by its own
  ('skg--content-with-fold-atoms', Neovim's 'content_with_fold_atoms');
  the server's atoms stand where the deciding headline is new.
