*** Ed : what I meant, and what the code says
A 'view' here is the server's record that some client has a buffer open
on a root: the server registers it when it renders ('open_views' in
'server/serve.rs'), uses it to know which buffers to re-render after a
save, and frees it when the connection closes. That record belongs to
one TCP connection. The Emacs client keeps one connection open for a
whole session; the tool opens a fresh connection for every command, so
the view it rendered in one command is gone by the time a later command
saves.

The question was whether the server would refuse such a save, or accept
it unsafely. I read the save path: it accepts the buffer whether or not
the view is registered, and the protection against saving old text
('stale' = rendered before the graph changed) does not depend on the
registration; it compares each node in the buffer with the graph. So the
tool's one-connection-per-command design is fine. The only effect of the
missing registration is that no other buffer on that connection gets
re-rendered, and the tool has none. No decision needed from you; closed.
