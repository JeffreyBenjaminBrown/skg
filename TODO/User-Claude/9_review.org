*** What do you mean by "one-shot commands with that '--out-dir'"?
**** Jeff : Ed's answer
A one-shot command is any ordinary run of the tool: 'view ID', 'save
FILE', 'diff', ... Each runs, prints, and exits. '--out-dir DIR' says
where it writes its files (and where it finds the ones it reads back).
The daemon is the exception: it keeps running. When a daemon is running
for DIR, a one-shot command told to use DIR does not talk to the server
itself; it hands its request to the daemon, which performs it on its
held connection. Since the last slice the same holds for any command on
the daemon's port, whatever its directory, so the sentence is now simply
"one-shot commands for that port".

** [jeff] Integrations into the diff view?

***** Jeff : Ed's answer: general, and mostly automatic
"Integration" is the watcher's word: when a '.skg' file changes on
disk, the server reads it and folds the node into the graph as a new
generation. That is general; it has nothing to do with the diff view.
Afterwards the server tells each connected client which of its open
views show a changed node, and the client re-renders those (only the
clean ones: a buffer with unsaved edits is left alone and told).

Your scenario: we both own 'skg-system'; I save into it while your diff
view is open. Your server integrates my files at once, since they are
not its own writes. If your diff buffer shows one of the nodes I
changed, it re-renders, and the change appears with its change facts.
What does not happen by itself: a node I changed that your diff buffer
does not yet show is not added as a new root, because a re-render keeps
a diff buffer's roots; for that you press C-c r u ('integrate unshown
changes', the diff view's own word, which is where the overlap of terms
comes from) or reopen the diff view. Making the re-render also add new
roots is a small server change; say if you want it in '10_plan.org'.
