* schema.tql constraint matrix

The schema is a useful checklist but not the future authority.  “Type-system”
means parsing/model types prevent malformed local shape; it does not replace a
cross-node validator.

| Schema fact | Rust home after cutover | Enforcement class | Required proof |
|-------------+-------------------------+-------------------+----------------|
| =node owns id @key= | node-set/graph identity validator and =nodes= map | hard cross-node error | duplicate PID tests |
| =extra_id owns id @key= | extra-ID ownership/index validator | hard cross-node error | duplicate extra ID tests |
| TypeDB's keys are per owner type, so PID/extra collision was not rejected | primary-wins lookup plus collision validator | hard migration/save error; lookup retains documented PID precedence | collision regression |
| =source owns source_name @key= | =SkgConfig= source parsing/validation | hard config error | duplicate source-name fixture |
| =user_owns_it= derives from path | config/path helper, never persisted graph authority | type/config-derived fact | owned/foreign source tests |
| =has_source= node card(1) | complete node home field plus configured-source validation | type-system + hard cross-node/config error | missing/unknown home tests |
| =extra_id= plays =has_extra_id= card(1) | one canonical PID per extra ID in =extra_id_to_pid= | hard graph error | reused-extra-ID test |
| relation/role declarations for contains, textlinks, subscribes, hides, overrides | graph-domain =NodeRelation=/role API and parsed relation fields | type-system for shape; validator for cross-node facts | all-role forward/inverse tests |
| node/source/extra entity plays declarations | typed node fields and config source map | type-system + graph constructor | malformed-role parsing tests |
| TypeDB binary relation endpoints | graph relation accessors and constructor | type-system/validator | raw/dangling member tests |
| no schema representation of edge recording source | stored member provenance plus active-source gates | hard semantic invariant | inactive-edge topology tests |
| no schema override monogamy/cycle rule | =override_invariants= | hard save/startup error for owned edges | monogamy, chain, cycle tests |
| no schema telescope rule | telescope validator | hard/warning according to existing invariant | telescope suite |
| no schema inverse-index equivalence rule | pure =InRustGraph= index validator | test/debug invariant | construction/update/delete equivalence suite |

Before deleting =schema.tql=, link each “required proof” to a concrete Rust
test/module and write the technical-doc explanation.  Retain raw dangling IDs
and recorded sources: the validator must not turn their intentional tolerance
into a fatal schema imitation.

* Test classification

** Port from TypeDB tests

- The relation-pair and recursive-document assertions in =tests/typedb.rs=
  have a graph contract and must be recreated as graph fixture tests.  Its
  create-only-node, delete-out-links, source-entity count, TypeQL row, and
  transaction assertions are storage-mechanism tests and are deleted or
  replaced by the graph/disk validations below.
- =tests/typedb/ancestry.rs= and =tests/typedb/paths.rs=: port contracts to
  explicit graph fixtures, including cycles, diamonds, depth limits, source
  gates, and deterministic ordering.
- =tests/typedb/search.rs= and =search/contains_from_pids.rs=: port ID
  canonicalization, relation lookup, containment, source/home provenance, and
  hidden/subscription behavior.
- TypeDB-dependent assertions embedded in view, source-set, override, merge,
  save, and git-diff tests: retain the user-visible behavior but swap the
  service fixture for graph/runtime fixtures.

** Replace with graph/disk tests

- =tests/typedb/update_typedb_from_saveinstructions.rs=: replace with save
  authority-order, graph forward/inverse-index, and Tantivy queue assertions.
- Delete/extra-ID coverage that only inspects TypeDB entities becomes disk +
  candidate-graph + index validation coverage; user-visible delete behavior
  remains in =grouped_saves=.
- =server/test_utils.rs= and =server/test_utils/guard.rs=: replace random DB
  names, driver setup, database cleanup, global graph installation, and serial
  DB guard with owned temporary fixture state.

** Delete as storage-mechanism-only

- =tests/typedb/delete_nodes.rs= TypeQL/database deletion mechanics.
- The =tests/typedb.rs= module root disappears after its graph-contract tests
  have moved to descriptively named modules; it is not itself retained as a
  misleading umbrella.
- tests of concept-document extraction, TypeQL strings, transactions, schema
  installation, database existence, and cleanup tooling, unless a pure
  tree-ID helper survives a caller audit.

The exact deletion is delayed until a test is either ported/replaced or shown
to have no behavior contract.  Do not use passing old TypeDB integration tests
as the post-driver proof.
