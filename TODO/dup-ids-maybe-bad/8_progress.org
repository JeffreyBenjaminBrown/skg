#+title: Progress on 7_plan.org

  The plan is implemented and its completion gate is green. The branch now
  treats privacy telescopes as checked values on both sides of the fold,
  prevents overPrivateText title/body text from crossing a restricted release boundary,
  offers an explicit save-time Hoist, and applies one owned-source rule to
  new relationships and aliases. The two warnings in Jeff's live data were
  repaired through the normal UI and a rebuild left no telescope-warning
  report.

* What landed

** Checked telescope boundaries and disk selection

   Commit '5bc332d3' made load-side 'Telescope' construction checked and
   private, added the corresponding private save-side
   'UnfoldedTelescope', and routed bulk load, one-pid reads, snapshots,
   export, and home lookup through the same owned-versus-foreign
   normalization. If owned and foreign sections claim one pid, Skg reports
   the collision, retains the owned telescope, and makes the foreign
   claimant semantically unreachable without modifying its files.

   Commit '0e218ad0' made unfolding produce a checked output batch and made
   the writer prepare and validate every path, serialization, ownership
   decision, and deletion before the first filesystem mutation. It cannot
   write a foreign non-home section after partially writing earlier levels.

** Independent title/body-text folding and release control

   Commit '41e82de8' folds title and body independently, records their
   source levels, and persists the resulting coarse 'overPrivateText_telescope' bit in
   'NodeComplete', 'NodeRust', and 'NodeTantivy'. Tantivy stores and indexes
   the bit so restricted search can exclude overPrivateText documents before matching.

   Four commits put one release policy in front of all textual outputs:

   - '3778bdd5': direct content views;
   - '22f15396': search and title lookup;
   - '13668a62': rerender, source-set switch, diff analysis, and export;
   - '6a9b4116': saved and collateral rerenders.

   Under source-set 'all', text is returned with a warning. Under a
   restricted source-set, affected pids are challenged before any text or
   match is returned; a retry approves only the reported pids. Restricted
   search is deliberately different: its prequery choice is include or
   exclude, because identifying matching pids before authorization would
   itself disclose the result. Noninteractive export fails closed unless
   '--include-overPrivateText-telescopes' is explicit.

** Save-time Hoist

   Commit 'f5703196' added the batched 'telescope-hoist-confirmation'
   protocol and matching Emacs and Neovim flows. The initial save explains
   which pids have title or body below home and returns without changing
   disk. An approved-pid retry rereads disk, reruns every ordinary
   validation, moves only title/body to home, preserves lower-level lists,
   writes the preflighted batch, and verifies that the resulting telescope
   is clean. Hoist authorization precedes fork authorization when both are
   needed.

** Source behavior and vocabulary

   Commit '24cf2890' centralized the default in
   'SkgConfig::relationship_default_source': a new writable outbound
   relationship from an owned node to a foreign node belongs to the
   owner's home unless the user explicitly chooses a more-private owned
   source. Save resolution, metadata, and the advisory source-info request
   now use that same rule. Alias 'relSource' is carried in metadata and
   round-trips; its current/default value is derived locally because an
   alias is not a graph edge and the edge-source endpoint needs two node
   ids.

   Commit '4660c433' completed the live 'level' to 'source' vocabulary
   change without a compatibility alias. Commit '7c5ea626' strengthened
   the deterministic-home regression test by rebuilding randomized source
   maps repeatedly.

** Documentation and ledgers

* Architectural outcome and implementation-time judgments

  No product choice in '7_plan.org' had to be reopened. The architecture
  proposed in its final section survived implementation. These local
  judgments are worth retaining:

  - 'Telescope' and 'UnfoldedTelescope' have different checked constructors
    and private fields. A trusted ordered disk input and a proposed disk
    output have different invariants; sharing one superficially general
    type would weaken both boundaries.
  - Owned-pid precedence is normalization of raw sections, not a filter on
    an already folded node. That keeps discarded foreign ids, aliases, and
    edges out of every graph and index, including snapshots and fallbacks.
  - Relationship defaults belong in 'SkgConfig', not separately in save
    resolution and the UI advice handler. The centralized method is now
    the rule for 'contains', 'subscribes_to', and 'overrides_view_of'.
  - A save may commit graph data successfully and then encounter an overPrivateText
    collateral view under a restricted source-set. The text-release gate is
    therefore after the successful save but before registering or sending
    that view's text; it withholds presentation, not the already-authorized
    graph mutation.
  - Restricted search never uses a pid allowlist for its first decision.
    It asks only include versus exclude before matching. Direct views,
    rerenders, titles, export, and Hoist use exact approved-pid lists.
  - The two hidden-from-subscriptions fixtures had encoded an owned source
    as more public than their foreign source. The old writer silently put
    inferred hides in foreign output; the checked writer correctly refused
    it. Commit '7915a2b1' reordered those fixture source maps so the public
    foreign data precedes the private owned overlay and the tests exercise
    their intended hide behavior.
  - The subscribee golden view still expected a source annotation for an
    owned-owner default. Commit '94ba687b' re-blessed it to the new single
    rule. This changed an expectation, not the architecture.
