** Measuring lines
A comment line is one that, with its leading blanks stripped, begins
with the language's comment marker: '//' in Rust (doc comments
included), ';' in Emacs Lisp, '--' in Lua, and '#' in Python and
shell. Every other line, blank ones included, counts as code, so
Python docstrings count as code. The figures above were counted this
way. The measurement is a one-time shell function, typed at the
repository's root, not a workspace member. It reads tracked files
only:
#+begin_src sh
measure () { # DIR EXT COMMENT_REGEX
  git ls-files -z -- "$1" | grep -z -E "\.$2\$" | xargs -0 cat \
  | awk -v re="$3" -v what="$1/*.$2" \
      '{t=$0; sub(/^[ \t]+/,"",t); if (t ~ re) c++; else k++}
       END {printf "%s: %d total, %d code, %d comments\n", what, c+k, k, c}'; }
measure server rs '^//'
measure elisp el '^;'
measure nvim lua '^--'
measure tools/skg-for-ai py '^#'
measure tests rs '^//'; measure tests el '^;'; measure tests lua '^--'
#+end_src
A slice measures at its base commit and at its last commit. For the
base, use a 'git worktree add' of it under '/tmp/claude-1000/' (run
'measure' there, then remove the worktree), or the numbers the

* Pitfalls the slices must respect
** A 'pub' function nobody calls raises no warning
The compiler's dead-code lint does not cover 'pub' items of a library
crate. So "nothing calls it" is proved by grep, not by the build:
before deleting a function, constant or file, run 'git grep -n -w
NAME' over the whole tree. That covers 'server/', 'tests/', 'tools/'
(several '[[bin]]' targets of 'Cargo.toml' live there, and
'thoughts/smsn/find-keywords.rs' is one too), 'elisp/', 'nvim/',
'bash/', 'windows/', 'shared/' and 'docs/'. A hit in 'docs/' or in a
comment is a citation: rewrite it to cite what stands. The survey ran
that grep for every name in slice 1 at 2ddc0ff8 and found no caller.
** The two visibility signals are read in a fixed order
'lower_collected_fieldIntents' ('lower.rs') extracts all the
'ForkeeVisibility' signals in their notes' first-emission order, then,
separately, all the 'ForkerVisibility' signals. Each reader in
'resolve_visibility.rs' takes them in a fixed order:
- 'validate_no_overlapping_forkee_hiderel_conflicts' reads the
  forker signals first, then the forkee signals;
- 'infer_hides_from_contains_removals' and
  'add_children_placed_under_members_as_such' chain the forkee
  signals, then the forker signals;
- the forkee-visibility loop in 'resolve_visibility' reads the forkee
  signals, then 'resolve_forker_visibility' reads the forker signals.
A merged signal (slice 2) must keep each of those orders: filter the
one list by its role, never interleave the roles. Order matters, for
instance, in 'add_children_placed_under_member_as_such': where one
node is a member under two notes, the later call's contains wins.
** The two visibility steps differ, so they stay two
The forkee-visibility loop ('resolve_visibility') and
'resolve_forker_visibility' look alike but differ in three ways:
- The forkee loop compares several sets by raw ID (for example
  'visible_content . contains (gnid)'). The forker step compares by
  'pid_else_raw_id' throughout.
- The forker step reads all of a member's content as drawn where the
  member is no mirror of the note ('is_mirror_of'). The forkee loop
  always subtracts what the note contains or hides.
- The forker step adds a fork; the forkee loop never does.
Merging them changes output in edge cases, so the merge is "Proposed
to Jeff" (P2). Slice 2 merges only the signals' types and the
collection's positions, not the steps.
** The unit tests of local collection name the signal types
'tests/new/local_fieldintent_collection/{traverse,types,extraction,lower}.rs'
pin which signal the traversal emits, with which contents, by naming
'ForkeeVisibility', 'ForkerVisibility' and the slots
'forkee_visibility' and 'forker_visibility'. These test only the
internals slice 2 merges. They take the merged names and keep every
expected value: the same member, the same role, the same lists.
** The diff view shares the goal's functions
'content_goal' returns early through 'diff_view::content_goal' with
the closure 'unintegrated', which passes '! walk . is_diff_view ()'.
Past that return the walk is not the diff view's, so the literal
'true' that 'content_goal' passes to 'content_goal_gnids' equals that
closure's flag. 'set_viewnodestats_in_viewforest' ('viewnodestats.rs')
passes '! is_diff_view' itself. Slice 3 keeps both flags where they
are.
** The compound folders' parties are already swapped
'compound_folder_parties' ('server/refresh/ancestry.rs') gives
'Folder::HiddenInForkPartner' its member as container and its note as
hider. It gives 'Folder::HiddenByForker' the note as container and
the forker as hider. So 'hidden_in_fork_partner (container, hider)'
read with each folder's own parties is each folder's goal, and
'hidden_by_forker (forker, note)' is 'hidden_in_fork_partner (note,
forker)'. Slice 3 relies on this. The hidden-by folder itself stays
(P3).
** 'forks_folder_members_shown' feeds the save
Its order is read by 'hide_report.rs', 'resolve_visibility.rs' and
'nodeMergeInstructionTriple.rs'. No slice changes it, and none merges
'forker_only_members' with 'indirect_members' (P4).
** The shared test helpers are declared in two targets
'tests/shared/view_and_save_helpers.rs' is declared, with
'#[allow(dead_code)]', in 'tests/grouped_forks.rs' and
'tests/grouped_saves.rs'. Its header names only the first; slice 5
fixes the header. A helper moved there from a file of
'grouped_views' (such as 'hidden_from_forks.rs') needs the module
declared in 'tests/grouped_views.rs' too. 'skg_files' in the shared
module keys files as "skgrepo/name.skg"; a local copy that keys them

** Comments state rules, and other comments cite them
Many comments in 'resolve_visibility.rs', 'goal.rs', 'visit.rs' and
