* Decide
** TODO The generated stop script lives at one fixed path
'bash/start-servers.sh' writes 'bash/stop-servers.sh' with its
own process group on every run, so a second instance (a scratch
server for a probe) overwrites the first's stop command. Agents
now save and restore it by hand. It would be safer if the path
depended on the config (e.g. 'bash/stop-servers-STEM.sh', STEM
the config's name) or if the script refused to overwrite a stop
script whose process group is alive. Your call; the plan's "What
stays" kept the file as it is.
** TODO Two function names in the start script
'run_skg_rerunning_on_exit' and 'run_skg_under_cargo_watch'
both rerun the server on exit; the first is named by what both
do. Would 'run_skg_without_hot_reload' and
'run_skg_with_hot_reload' read better? Cheap either way.
** TODO The log file is still 'logs/cargo-watch.log'
Both clients name it when a connection fails. Without hot reload
the name is slightly wrong. Renaming touches two client files
and the troubleshooting doc.

* Suggestions for the advice
** A pitfall about shared generated files
'orchestration.org' could say: before a brief sends an agent to
run a script that writes a fixed-path file the live system
depends on, name that file in the brief as one to save and
restore. Slice 1 found this the hard way.
** Measured expectations belong to one cause each
Plan 1_1 expected 557 ms for slice 3 from a measurement that
covered one of the slice's two changes. Harmless here, but a
plan's number should say which change it measures.
