* DONE What exists: 'skg-describe-at-point'
'skg-describe-at-point' (C-c v ?; ':SkgDescribeAtPoint' at
<localleader>v? in Neovim; 'describe VIEW HANDLE' in skg-for-ai) says
in plain sentences what the headline at point is, when it is a folder,
then what each herald it shows means, the most informative first,
with its own counts, ancestor letters and skgrepos read out. The
server writes the sentences ('server/herald_descriptions.rs'; the
"describe heralds" endpoint in 'docs/api-and-formats.org'), so all
three clients share one text. Its unit tests require a sentence for
every path the herald rule table renders and for every folder, so a
herald cannot be added without one; at run time a path without one
reads "No description yet for PATH.".

The sections below are what the old plan for this feature asked for
beyond that, still unbuilt. The plan's catalogue of heralds is gone:
it named relations and heralds that no longer exist (subscribes,
overrides, U/D fractions, Pk, the 'C-c p' path commands, staged and
unstaged X/M markers). 'docs/heralds.org' is the legend, and the
sentences follow it.
