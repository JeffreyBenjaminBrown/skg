* Agreed behavior
** Counts describe the active graph
Use distinct resolved node identities, not occurrences of links, extra-ID
spellings, configured source names, or rendered rows. Apply both endpoint
home-source visibility and relationship relSource visibility where the
relationship has that gate. Unknown targets do not count as resolved
nodes. Follow literal relationships without override substitution when
computing these statistics.

Herald facts describe the latest server-rendered graph snapshot. Ordinary
unsaved title/body edits do not silently become committed graph statistics.
Link annotations, however, should look up the IDs currently in the buffer.

** Link herald: I/SLT
S counts distinct visible nodes linking to this node. T counts its
distinct visible resolved targets across title and body. I counts the
subset of S whose nodes have any of: nonempty body text, at least one
visible direct content node, or more than one distinct visible resolved
link target. Count each such source once, even if it meets all criteria.
Use the existing body normalization invariant; whitespace alone is not
body text. Repeated links and alternate IDs for one target do not satisfy
the multiple-target criterion by themselves. Do not retain the old
title-versus-label surprise predicate or its special self-link exclusion.

I and S are numbers in the explanation, not literal letters to print.
Use L as the separator between incoming and outgoing facts. T is useful
even with folded bodies and repeated links; it need not equal the number
of link labels visible in the buffer.

*** Examples without ancestor flags
| I | S | T | Rendered text |
|---+---+---+---------------|
| 2 | 5 | 3 | 2/5L3         |
| 0 | 5 | 3 | 5L3           |
| 2 | 5 | 0 | 2/5L          |
| 0 | 5 | 0 | 5L            |
| 0 | 0 | 3 | L3            |
| 0 | 0 | 0 | no L token    |
| 5 | 5 | 3 | 5/L3          |

** Subscribee-as-such content herald: CU/D
For a subscribee B occurring under subscriber A, D is B's visible direct
content count. U counts those members after subtracting what A visibly
hides or directly contains. Use the existing integration semantics:
resolve extra IDs, but do not identify an overrider with the node it
overrides. Hidden content is already dealt with, so it is excluded from U
but included in D when visible under B.

This numerator belongs to the occurrence: the same B can have different U
under different subscribers. It must agree with the membership used to
populate that occurrence, before display folds and node budgets. Do not
count folder rows, expanded descendants or override substitutes as new
content members. Count resolved visible members, not Unknown placeholders.

Keep the incoming contains side unchanged. An entire token can therefore
be '2C3/8'. Outside the subscribee-as-such role, retain ordinary contains
rendering.

*** Examples for the outgoing side, without ancestor flags
| U | D | Rendered content side                         |
|---+---+-----------------------------------------------|
| 2 | 8 | C2/8                                          |
| 0 | 8 | C8                                            |
| 8 | 8 | C8/                                           |
| 0 | 0 | no outgoing side; retain C if incoming exists |

** One fraction grammar for L and C
The numerator is a subset of the denominator. Validate that its count
does not exceed the total; this is an invariant, not an invitation to
silently clamp inconsistent facts.

*** Apply omission in a defined order
When the total is zero, omit that side. When the numerator is zero,
omit the numerator and slash, and render the total with ordinary ancestor
compression. Otherwise render numerator, slash, and denominator.

When nonzero numerator equals denominator, omit the denominator entirely,
but keep the slash. Compare actual counts before suppressing numerals.
Thus '5/5L' becomes '5/L', 'C5/5' becomes 'C5/', and an interesting sole
parent source renders 'a/L'. A slash must never stand for 0/0.

*** Ancestors can appear on either side of the slash
Preserve the existing tracked-ancestor policy and generation meanings,
including scaffold levels. Add incoming-link ancestor facts; do not
expand which ancestors are tracked merely for this feature.

Print each ancestor flag once within a fraction: in the numerator if its
node is in the subset, otherwise after the denominator's numeral. The
denominator's count still includes the subset. Keep full counts and full
membership facts on the wire; this partition is a rendering choice.

Suppress a numeral when its members are completely accounted for by the
ancestor flags, consistently with ordinary relations. For a fraction's
denominator, account for ancestor members already named in the numerator
as well as those printed after the slash. Do not count printed characters
as members: a generation rendered as '{27}' is one flag, and a repeated
node identity is not several distinct members.

| Facts                                   | Rendered text |
|-----------------------------------------+---------------|
| Parent is sole interesting source of 5  | a/5L          |
| 1 of 5 interesting; parent is another   | 1/5aL         |
| Parent is sole source and interesting   | a/L           |
| Parent is sole source and uninteresting | aL            |
| Sole outgoing target is parent          | La            |
| 3 outgoing targets, including parent    | L3a           |

If two distinct tracked ancestors a and b are the only inbound sources,
with only a interesting, 'a/bL' expresses numerator 1 and total 2. This
follows the no-repeated-flags and fully-explained-count rules together;
the denominator is not the uninteresting remainder. Explain this example
in the legend and inspector.

*** Interesting numerals, ordinary relation letters
Use the interesting style for displayed I and U numerals, and for any
displayed incoming or outgoing override count, including one. Slashes
and denominators retain the relation's ordinary/birth style. O itself
retains purple or the black-on-white birth style. Other relations retain
their established base and birth behavior.

Ancestor letters retain their ancestor style, even when they replace an
interesting numeral. Do not restore a redundant numeral merely to paint
something orange. 'Oa' and 'aO' lose no count information by omitting one.

*** Dim only a
Give a a separate, muted yellow treatment, approximately one quarter the
current visual prominence, with legible lettering. Keep b and all higher
ancestor markers at their existing brightness. This requires styling
individual ancestor flags, not applying one face to the entire string.
Choose the precise colors by visual checking; no color approval round is
needed. Support the same distinction in both clients.

*** Pink h means substitution at this occurrence
Introduce the named 'confusable' style as a pink foreground. Immediately
after O, insert h exactly when that occurrence has 'overridesHere'. It
precedes the outgoing count and ancestor flags: for example, '2Oh3'.
Use the existing marker as the source of truth, never infer substitution
from override counts or birth status. An override folder/path occurrence
without 'overridesHere' gets no pink h.

Preserve the marker's original ID and all save validation/round-trip
semantics. A marked occurrence must still expose its h even if ordinary
count omission would otherwise leave no O token. Counts-only phantoms do
not acquire substitution markers.

The eighth ancestor may also be h. Its ancestor style remains yellow;
the substitution h is pink. Jeff accepted the ambiguity in unstyled text.
Document and explain the difference rather than changing either notation.

** Link annotations
*** Source suffix
'skg-toggle-source-overlay-on-links' toggles display-only suffixes for
Skg links in titles and bodies in the current buffer. Default the suffix
off. Implement the corresponding buffer-local Neovim action.

For a visible resolved target, show its home-source abbreviation using
the existing green source style and source-label formatter. Resolve extra
IDs first. Annotate the literal target, not its overrider and not the
relationship's relSource. Keep following a link an exact-ID visit.

Missing, inactive and not-yet-known targets need distinct unavailable
states. Do not invent a source name for them, or expose inactive node
titles/home-source labels through this feature. Exact suffix punctuation
is an ordinary implementation choice; use the existing source vocabulary.

*** Broken links
Color a Skg link pink and underlined only when the current server graph
confirms the target is missing after extra-ID resolution. Preserve link
navigation so attempting it can explain the failure. Apply this in both
clients even while the source suffix is off.

Inactive targets, pending lookups and transport errors are not evidence
of a broken link. Do not apply the rule to arbitrary web/file links.
The shared confusable style supplies pink; link presentation supplies
underlining, without requiring the herald's h to be underlined.

*** Lifecycle and asynchronous correctness
Preserve toggle state across buffer rerenders and major-mode setup.
Refresh annotations after link edits, saved/collateral view replacement,
successful graph-changing operations, source-set changes and reconnects.
Refresh even when a changed target has no headline in the annotated view;
it may appear only as a link. A deleted target must become pink, and a
newly created target must stop being pink.

Batch and deduplicate target lookups, debounce edits, and reuse results
within the appropriate graph/source-set lifetime. Never make one network
request per link, block typing on a lookup, or rescan the whole project
per edit. Discard replies for obsolete text, changed source sets, dead
buffers and old connections. Associate replies with the right requests
when several buffers are active. Clean up only this feature's overlays,
extmarks, timers and callbacks.

Annotations must not change buffer text, modified state, undo history,
saved files, clipboard text or navigation offsets. Verify interactions
with hidden Org link syntax, herald overlays, folds and Unicode labels.

** Inspectable explanations
Provide a small read-only inspect-herald command in each client. Explain

using actual counts rather than reverse-parsing abbreviated display text.
Include subset/total meanings, ancestor generations, active-source scope,
birth meaning, and substitution when present. Make the relevant existing

For a substituted row, identify its original and drawn node and explain:
edits affect the drawn node; parent membership still refers to the

missing titles. Explicitly distinguish pink h from ancestor h.

Give missing/inactive/pending links inspectable status explanations too.
Use one semantic interpretation for rendering and explanations in each
client, so an explanation cannot drift from the displayed counts.
