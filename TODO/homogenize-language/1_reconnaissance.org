** How I chose recommendations
*** The code wins ties
Where the code already settled on a name, I recommend the docs follow
it, unless the code's name collides with something else.
*** Rename only for a collision or a stale name
'names.org' says not to rename gratuitously, so I propose a rename only
where two names mean one thing, one name means two things, or a name
outlived a change.
*** Extend the "merge" rule to other overloaded words
The glossary already says "merge" is always qualified ('nodeMerge' vs
'instructionMerge'). That rule is cheap and works. Several other words
need the same treatment rather than a rename (see [[*One name, several things][homonyms]]).
*** Cost tiers
Each proposal is one of three kinds:
- *prose*: docs, comments, TODO files.
- *identifiers*: Rust/Lisp/Lua names, which the compiler mostly finds.
- *formats*: wire atoms, YAML keys, file names. These touch saved data
  or both clients, and per 'no-legacy-support.org' would need a
  one-shot migration, not compatibility code.

* Stale names: renames you already decided that never finished
These are the cheapest wins: the decision is made and only the sweep
remains.
