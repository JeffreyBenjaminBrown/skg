****** Codex: importing and exporting are two separate operations
Import reads your existing files and creates Skg nodes. After that, Skg stores
the material in '.skg' files, with a node for each document and each heading.
It no longer depends on the original documents for its contents.

Later, export reads Skg nodes and writes ordinary '.org' documents. It needs

documents. The question here is whether the importer should supply those
instructions automatically, so you do not have to add them by hand later.
******* Glossary
******** File-root node
The Skg node representing one imported document as a whole. Its descendants
represent that document's headings. It is distinct from the filesystem
folder that held the input file.
******** Import record node
The node you already requested: it records when the import ran and its
arguments, and contains the imported file-root nodes. It answers 'What did
this import create?' It does not instruct the exporter to write files.
******** Export root
A Skg node selected to become a separate exported document, together with
its contained material. A file-root node is a natural choice, but merely
being imported does not currently make a node an export root.
******** Export marker
A small instruction node contained by an export root. The existing exporter
recognizes it because its title links to Skg's export-instruction node and
its body specifies 'target_filepath'. The marker itself is omitted from the
exported document. It is ordinary stored Skg data, not an import-time flag.
******** Target filepath
The output filename and any subfolders, relative to the export output
directory. The existing marker omits the extension: 'target_filepath = guide'
means 'guide.org'. 'target_filepath = tutorials/guide' means
'tutorials/guide.org'. The exporter supplies '.org'.
******** Output directory
The folder you choose when running export. For example, choose '/project/docs'
and a marker with 'target_filepath = tutorials/guide' produces
'/project/docs/tutorials/guide.org'. It is separate from the Skg source
directory that stores '.skg' files.
******* Example using your intended workflow
Suppose you import '/project/docs', containing 'setup.org' and
'tutorials/start.md'. Import creates a file-root node for each, plus the
import record containing both. You then edit their contents in Skg.

If we automatically add export markers, the 'setup' file root gets a marker
with 'target_filepath = setup'; the other gets
