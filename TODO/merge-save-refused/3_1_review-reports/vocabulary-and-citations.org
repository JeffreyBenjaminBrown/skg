* Ranked findings
** 1. A re-sent save is said to be stale; often it is not
'api-and-formats.org':488-489, 'COMMANDS.org':82-83,
'COMMANDS-nvim.org':97-98, 'skg-request-save.el':850-851,
'save.lua':876-877, 'tools/skg-for-ai/README.org':1362-1363.
After the overPrivateText rerender is withheld, the buffer keeps
its old baseline. Re-sent, the nodes the save edited now equal
the graph, so the noop filter drops them: nothing is written for
them and nothing is stale. Only a graphnode written afresh (a
container gaining the same new child again) is stale; a new root
is simply created twice. The reason not to re-send is that the
save would apply again. Cheap: reword all six.
