#+title: Plan 4 reviewed: three refinements and two renamings
* Verdict
Plan 4 did what it set out to do, in seven slices and about an
hour and a half of agent time. A buffer that still shows a
graphnode as the server drew it, while the graph changed it, no
longer refuses the save: the graphnode is left as the graph has
it and the response says so, whichever path the copy took (its
own Save, a fork, a move back, a write-protected occurrence). A
dirty view no longer conflicts with a save through a link, in
either direction. A view request no longer lands in a buffer of
the diff view. The runtime generation starts at the epoch again,
and the save's phases and delete propagation's passes carry
names, not numbers.

The probes found one defect the suites missed, as they did after
plan 2_2: once links stopped blocking a save, the save redrew the
dirty view that had been in its way, and both clients would have
replaced the buffer and lost the edits. Slice 6 fixed it on the
server, which now skips every dirty view when choosing collateral
views, and in both clients, which no longer replace a buffer with
unsaved edits. Slice 7 closed a second gap (a graphnode shown
only write-protected was still refused after a retitle elsewhere)
and applied the vocabulary review's cheap findings.

Two renamings the vocabulary review proposes are costly and are
yours to decide (section "Decide").

* What the user sees differently
** By decision
- A buffer that shows a graphnode as it was, unedited, while the
  graph changed it, saves; the graphnode is left as the graph has
  it, the redraw shows it so, and the response warns which ones.
  The stale refusal fires only for an edited or deleted outdated

  direction, no longer blocks the save.

- The server's log numbers its generations from the epoch's
  microseconds again.

The glossary now defines "outdated" (the baseline's copy differs

the buffer). The reviewer calls the pair confusible and the
rename costly; it is used in two identifiers and five docs. I
would keep both, since the glossary states the difference in one
line, and the alternative ("changed under the user" for outdated)
is longer wherever it would go.

* Suggestions for the advice
- 'plans.org': when a plan removes a refusal, it should ask what
  else that refusal was preventing. The dirty-view conflict was
  also what kept a dirty view from being redrawn; removing one
  half exposed the other.
- 'orchestration.org': when Jeff edits a planning file during a
  run, agents stage only their own hunks (a HEAD-plus-edits copy
  written to the index); this worked seven times and should be
  the written rule, not a brief's instruction.
