*** Deviations from the plan's how
**** One commit, not server then clients
The server refuses an envelope without the field, and refuses an
unknown field, so a server-only commit, or a clients-only one, leaves
every client save refused at that revision. One commit keeps each
revision working.
**** The tool's baseline is the '.full.org' file
The sidecar ('.view.json') has no 'content' field. The full view file
is the response's 'content' as the server sent it, never edited by
the tool's user, and is already what 'other_views_text' sends as a
dirty view's baseline; 'save' and 'extend' send it
('SavedView.full_text'). The forest commands' unchanged save sends the
fresh view's 'content'; 'new' sends the empty baseline, a new empty
view's. The README's "The full view" says so.
**** 'raw' gained '--baseline FILE'
'raw --saved-buffer FILE' builds the envelope itself, so it needs a
baseline: FILE's text with '--baseline FILE', else the empty one. The
envelope is built in one place, 'save_envelope_text'.
**** A new empty view already captured its baseline
Both clients open a new empty view through
'skg-open-org-buffer-from-text' / 'open_org_buffer_from_text', which
already capture the clean baseline (the empty text). No code change;
the existing new-empty-view tests now assert it.
**** A client refuses locally a view without a baseline
'skg--saved-buffer-baseline' (Emacs) and 'save.saved_buffer_baseline'
(Neovim) signal an error before anything is sent; the save's existing
local-failure path unwinds the locks. No client view should lack one.
**** The Neovim envelope has its own function
'save.serialize_save_envelope', mirroring Emacs's
'skg--serialize-save-envelope', so the field can be tested without a
server.
**** The unused parameter is allowed until slice 3
'update_from_and_rerender_buffer_with_approvals' takes 'baseline'
under '#[allow(unused_variables)]' with a TODO naming slice 3, which
should remove both.
**** Not guarded: a bare symbol parses as text
The 'sexp' crate parses a bare symbol and a quoted string alike, so
'(baseline unavailable)' reads as the text "unavailable" (an Org text
with no headlines, which writes nothing). 'saved-buffer' has the same
property. No client sends it; a list such as '(present "...")' is
refused.
