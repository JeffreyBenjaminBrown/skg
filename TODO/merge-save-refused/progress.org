*** Deviations from the plan's how
**** One commit, not server then clients
The server refuses an envelope without the field, and refuses an
unknown field, so a server-only commit, or a clients-only one, leaves
every client save refused at that revision. One commit keeps each
revision working.
**** The tool's baseline is the '.full.org' file
The sidecar ('.view.json') has no 'content' field. The full view file
is the response's 'content' as the server sent it, never edited by
the tool's user, and is already what 'other_views_text' sends as a
dirty view's baseline; 'save' and 'extend' send it
('SavedView.full_text'). The forest commands' unchanged save sends the
fresh view's 'content'; 'new' sends the empty baseline, a new empty
view's. The README's "The full view" says so.
**** 'raw' gained '--baseline FILE'
'raw --saved-buffer FILE' builds the envelope itself, so it needs a
baseline: FILE's text with '--baseline FILE', else the empty one. The
envelope is built in one place, 'save_envelope_text'.
**** A new empty view already captured its baseline
Both clients open a new empty view through
'skg-open-org-buffer-from-text' / 'open_org_buffer_from_text', which
already capture the clean baseline (the empty text). No code change;
the existing new-empty-view tests now assert it.
**** A client refuses locally a view without a baseline
'skg--saved-buffer-baseline' (Emacs) and 'save.saved_buffer_baseline'
(Neovim) signal an error before anything is sent; the save's existing
local-failure path unwinds the locks. No client view should lack one.
**** The Neovim envelope has its own function
'save.serialize_save_envelope', mirroring Emacs's
'skg--serialize-save-envelope', so the field can be tested without a
server.
**** The unused parameter is allowed until slice 3
'update_from_and_rerender_buffer_with_approvals' takes 'baseline'

**** Not guarded: a bare symbol parses as text
The 'sexp' crate parses a bare symbol and a quoted string alike, so

with no headlines, which writes nothing). 'saved-buffer' has the same
property. No client sends it; a list such as '(present "...")' is
refused.

*** Deviations from the plan's how
**** Two commits
The check and its error first, with the request still carrying an
unused rendered-at; then the removal across server, clients, tests and
docs, which cannot land apart (a client that sends no rendered-at
needs a server that does not ask for it).
**** A body with trailing whitespace on disk would make every save stale
The noop filter compares with the graph as stored, but a view draws
a body's trailing whitespace and the parser trims it. So the
baseline's copy of any node whose file has such a body survives the
filter, and so does the buffer's write of it, even untouched: every
save of a view showing such a node would have been refused, until a
strip. The baseline's writes are therefore filtered once more,
against the graph as drawn: the graph's body put through
'strip_trailing_whitespace_from_body' ('graphnode_as_drawn' in
'save_staleness.rs'). The error's comparison uses the same form, so
it does not report whitespace. A test covers it
('trailing_whitespace_on_disk_does_not_make_a_buffer_stale'). The
plan's "the parser trims what the strip trimmed" holds; the plan did
not anticipate the same asymmetry before any strip.
**** The title line shows the graph's title
The plan's example shows the old title on the "Title:" line, but also
omits that line when the graph lost the node; so it is the graph's
title, now. The old title appears in the title aspect when it differs.
**** The baseline's parse errors refuse the save
'org_to_viewforest' returns, beside the viewforest, a list of parse
errors; a non-empty list refuses the save with the "could not be
read" message, as a failure does. A server-drawn baseline has none in
every suite.
**** Aspects beyond 'node_changes_between'
The aspects named are those the noop filter compares, so a stale node
always names at least one: the aliases are named also when only their
relRepos changed; the flags when only their order did; the content,
when its IDs did not change, says "reordered" or "the skgrepos of its
relationships". Subscriptions, hides and overrides are named when the
baseline specifies them and they differ.
**** The startup generation is 0
'startup_generation' (microseconds since the epoch) existed so a
restart could not make an old buffer look fresh. With it gone the
generation starts at 0; it names reload notices, rerender passes and
rebuilt search-index folders (with the process ID), none of which
compare across processes.
**** The foreign test lives in 'save_stale_buffers.rs'
The fixture gained a foreign repo cheaply ('theirs/n.skg'). Editing n
asks to fork it; the stale check runs before the fork confirmation and
names n through the fork spec's original.
**** The tool's search tells a view from a message by its warnings
'fetch_search_view' told a no-match message from a view by the
missing rendered-at; a view response has a 'warnings' field, a
message does not.
**** Client tests renamed and trimmed
'tests/elisp/test-skg-rendered-at.el' became
'tests/elisp/test-skg-baseline.el' (a view keeps the text each
response draws as its baseline, and a refused save keeps it); the
Neovim 'skg.save rendered-at' block became 'skg.save baseline'. Tests
that only asserted the absence of rendered-at were dropped.
