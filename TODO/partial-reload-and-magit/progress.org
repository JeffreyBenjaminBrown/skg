** authoritative source inventory and pre-parse selection (in progress)
- Replaced the independently mutable source 'HashMap' and 'source_order'
  with 'SourceCatalog': one ordered lookup catalog which retains each raw
  configured path and resolved physical-directory identity.  Mixed named
  and unnamed sources now retain declaration/privacy order.
- Config load now creates owned directories, validates foreign directories,
  canonicalizes source identity and rejects two entries which alias the same
  physical directory, naming both entries in the error.
- Added one exact direct-child classifier.  Reload no longer treats an
  arbitrary descendant or a path-prefix sibling as a source file.
- Added the shared path-selection boundary in 'source_files.rs'.  Bulk load
  and one-pid load now choose owned same-filename candidates before reading
  YAML, so a malformed ignored foreign collision is opaque.  The warning
  carries winner and loser paths internally, while the existing aggregate
  telescope report still receives its source-level form.
- Diff snapshot enumeration now ignores nested '.skg' files and applies the
  same path selection before parsing full HEAD, index and worktree snapshots.
  Focused source, reload-path, malformed-collision and 28 diff-analysis tests
  pass.
- The connection handshake now carries the server's ordered, normalized source
  inventory.  Emacs and Neovim cache that inventory and use it in preference to
  reparsing TOML; their TOML fallback also handles unnamed sources correctly.
- Ignored owned/foreign collisions survive initialization and rebuild as
  structured telescope warnings.  The handshake makes them prominent and
  persistent in a dedicated Emacs or Neovim warning buffer, including the
  winning and ignored paths.
- Validation after this slice: all 176 Rust library tests under nextest, all
  312 Emacs tests, and the complete Neovim suite pass; 'git diff --check' is
  clean.  (The four source/privacy tests which race through shared global graph
  state when run in one process pass under the repository's required nextest
  process isolation.)

** selected-store and index generations (in progress)
- Replaced the graph-only 'ArcSwap' payload with one immutable
  'SelectedStoreState': graph snapshot, monotonic graph generation, BLAKE3
  selected-path manifest, per-path index state, cyclic-root slot and derived
  store health now publish as one value.  Existing graph readers retain a
  cheap 'Arc<InRustGraph>' from that publication.
- Initialization and rebuild build the manifest from the exact retained bytes
  they parsed.  Save and node merge update it from their prepared serialized
  bytes; ignored foreign files are not falsely called selected.  The
  connection handshake now exposes graph generation, path outcomes and store
  health, and both clients cache that authoritative baseline.
- The Tantivy background writer now assigns monotonic generations and retains
  'Pending', 'Committed' or 'Failed(reason)' for each.  Exact and captured-
  through waits are available; enqueue failure and worker panic become failed
  generations.  A transition publishes its awaiting-index paths before the
  task can run, and the worker promotes precisely those paths by atomic CAS.
- Save/reload no longer acknowledges before the exact Tantivy generation.
  Node merge drains older queued work before its direct write.  Whole-corpus
  whitespace normalization now takes the graph writer lock before scanning,
  drains the captured older index generation and publishes graph plus manifest
  together.
- TypeDB recovery now reconstructs from the immutable candidate graph rather
  than rereading possibly bad disk.  Reload additionally attempts restoration
  of the prior graph projection and marks TypeDB poisoned if neither complete
  reconstruction succeeds.

** stable reload transaction (in progress)
- Path parsing before the writer lock resolves identifiers only.  Under the
  lock, reload captures every possible section path as exact bytes or absence,
  applies owned/foreign selection, parses/folds, and rereads every captured
  path before the first store mutation.  A mismatch changes no store.
- Each legal telescope updates the selected manifest from its captured bytes;
  fatal telescopes keep both their prior graph node and selected digests.  The
  final graph undergoes pure distinct-ID-claim and override validation.
- An extra-ID change invokes the complete normalized-corpus fallback, validates
  it, rechecks its complete selected manifest, and derives graph definitions by
  comparing old and new graphs.  A test proves that claiming an untouched
  node's primary ID rejects the transaction without advancing graph or
  manifest.
- Validation after these changes: 180/180 Rust library tests, the combined
  135 save/source integration tests, all 312 Emacs tests and the complete
  Neovim suite pass.

** request-scoped response protocol (in progress)
- Every foreground operation now receives a fresh connection-local request
  ID.  The server echoes it on every frame, names the frame kind independently
  of its payload type, and marks exactly one terminal frame.  Search's snapshot
  response is the sole same-ID continuation; authorization retries are new
  requests.
- Both clients retain handlers in per-request records and serialize complete
  operations through a FIFO coordinator.  A stale or unknown response cannot
  reach a newer like-typed handler.  Terminal cleanup advances the queue once,
  including when the selected handler itself errors; parser state is reset
  only for a new or abandoned connection.
- Rerender privacy challenges are terminal rather than beginning a synthetic
  empty rerender stream.  The client unlocks immediately and schedules any
  approved retry as a new request.
- The wire contract and its search continuation are recorded in
  =api-and-formats.md=.  Validation after this slice: 182/182 Rust library
  tests in one serial process, all 314 Emacs tests and the complete Neovim
  suite pass; =git diff --check= is clean.

** durable incident identity and explicit ID selection (in progress)
- Request records can now carry a durable incident UUID.  Both clients copy
  it into the request, the server echoes it on every frame and clients reject
  a frame whose incident identity differs.  Search continuations retain it;
  retries may use a new request ID without losing the episode identity.
- =skg-reload-from-id-stack= opens a transient copy of the canonical stack
  with a buffer-local, single-keyword Org TODO sequence.  Standard S-left and
  S-right mark =TO-RELOAD=; C-c C-c submits deduplicated IDs, while C-x C-s
  explains that this buffer cannot save or alter the real stack.
- Reload requests now accept paths and primary or extra IDs together.  IDs
  resolve against the selected graph before the writer transaction and name
  their complete possible cross-source telescope.  The terminal response
  reports each requested ID, primary PID, considered paths and acknowledged
  or rejected status.  The selector clears only acknowledged marks and keeps
  rejected marks with transient reason overlays.
- Expected reload failures now terminate as a failed =reload-paths= result
  rather than bypassing the request's handler through the generic error type.
  Validation after this slice: 184/184 serial Rust library tests, all 318
  Emacs tests and the complete Neovim suite pass.

* Component 4 (recovery) -- NOT STARTED; assessed, no stumper
The three-=oops-N_*=-branch recovery (plan Component 4) is the remaining
work. The one flagged risk -- rendering a telescope from an in-memory
graph snapshot to its on-disk BYTES without writing to disk -- is
FACTORABLE, not a stumper: =write_nodecomplete_telescope= (=one_node.rs=)
already does =unfold_node= -> =nodefs_from_section= -> =node_fs.to_yaml()=
-> path; factoring that into a =Vec<(path, yaml)>= producer (leaving the
=fs::write= to the caller) gives exactly the bytes git2 blob-building
needs. Everything else is new but understood: git2 0.18 plumbing
(blob/treebuilder/commit/reference, no checkout), =repo.state()= /
=head_detached()= precondition guards (added fresh), a per-connection
=PendingIncident= (=g_pre=, =g_post=, touched set, base commits), and a
second "reload recover" request offered/confirmed like the fork flow.
No git-writing code exists in the server yet, so this is all additive.

* changes to the plan's envisioned order
- Within Component 1, the plan's batch "scoped duplicate-ID check" (plan
  1.4 step 6) is NOT implemented; only the override-invariant batch guard
  is. Duplicate-IDs remain caught by a full rebuild, not by a scoped
  reload. Tracked under "imperfect" below.
- Built in the order Components 1 -> 2 -> 3 (server core, mutex, Emacs)
  as planned; Component 4 (recovery) is the remaining phase.

* what's imperfect about what's done
- Override-invariant rejection is coarse: a violation rejects the WHOLE
  reload batch (all touched telescopes keep last-good), not just the
  offending one. Safe, but blunt. (Planned as acceptable.)
- Scoped duplicate-ID detection on reload is not implemented yet (see
  above). A reload that introduces a cross-source duplicate ID would be
  applied; a subsequent full rebuild would catch it.
- Collateral re-render has no dedicated open-view integration test: the
  parity tests register no views, so the re-render path early-returns in
  them. It reuses the heavily-tested save collateral path, but a reload
  test that registers a view and asserts a streamed CollateralView is
  still owed.
- Component 3 (elisp) is byte-compiled but not runtime-verified (no live
  Emacs/magit/server here). The change-detection scans all =.skg= files
  on each magit refresh via mtime (cheap); if a large tree lags, upgrade
  to hashing only mtime-changed files.

* choices determining the future
- Reload's store commit reuses =apply_define_nodes_to_stores= directly
  (never =update_graph_minus_nodeMerges=). This is the mechanism that
  keeps reload from writing any =.skg= file. Any future change to the
  save pipeline must preserve that this function, with write_fs=false,
  performs no filesystem writes.
- =reload_touched_telescopes= is async and pub, so tests can =.await= it
  and the handler =block_on=s it. The recovery work (Component 4) will
  add a =pending_incident= parameter here and to the dispatch arm.
- The write mutex is a tokio async mutex acquired under
  =block_on=-per-connection-thread. If the server ever moves to a shared
  multithreaded async runtime, revisit that the guard is not held across
  a point that could deadlock the runtime.
