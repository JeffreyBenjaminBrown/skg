* Refactoring the clients' tests and the integration tests
  The territory: what each integration directory runs
  ('tests/integration/*/run-test.sh', 'test-emacs.el', 'test-nvim.lua'),
  the Emacs unit tests ('tests/elisp/') and the Neovim specs
  ('tests/nvim/*_spec.lua'). The shared code they call lives in the
  harness ('tests/integration/test-lib.sh', 'test-wait.el',
  'test-nvim-lib.lua', 'tests/nvim/helpers.lua'), which
  'tests-harness-and-bash.org' covers; helpers were added there because
  that is where shared test code already lives. 'elisp/skg-test-utils.el'
  is in 'elisp/', outside this territory.
** How to check a change here cheaply
   A 'run-test.sh' can be run without a server: copy
   'tests/integration/' (old and new) into a scratch folder, append to
   its 'test-lib.sh' stubs of 'find_available_port' (a fixed port),
   'start_skg_server' (copy '$TEMP_CONFIG' out), 'run_client_test' and
   'cleanup', run every script, and diff the configs and exit codes.
   One directory, both clients: 'cd tests/integration/DIR &&
   SKG_TEST_CLIENT=nvim ./run-test.sh' (needs 'target/debug/skg').
   The runner reports 'CLIENT/DIR' for each directory with a
   'run-test.sh' (Neovim only where 'test-nvim.lua' exists): 80 names.

** Back up and restore '.skg' fixtures with two shared helpers
   15 'run-test.sh' ('aliases-view-request', 'containerward-view-request',
   'save_collateral_*', 'save_lock_lifecycle', ...) each write a
   'backup_and_reset_test_data' and 'cleanup_test_data' that copy
   'NAME.skg' to 'NAME.skg.backup.TIMESTAMP' and back. Two helpers
   ('back_up_skg_file DIR NAME', 'restore_skg_file_from_backup DIR
   NAME') would shrink each loop body to a call. Risky in the details:
   some remove the file when there is no backup, some do not, and the
   backup and the reset of a file are interleaved in one loop; keep
   each variant's behaviour, and check the fixture folders are clean
   ('git status') after each run.
