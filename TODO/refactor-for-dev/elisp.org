* Refactoring the Emacs client ('elisp/') for the next agent
Behaviour-preserving refactors only; see the brief's rules. Two
things to know before any change here follow.
** A new file must be registered with 'skg-reload'
'skg-reload' unloads every feature in 'skg--reload-unloaded-features'
('elisp/skg-reload.el'), and 'tests/elisp/test-skg-reload.el' fails
if a provided feature is in neither that list nor
'skg--reload-kept-features'. A new file's feature goes in the first.
New functions must not go in the kept files ('skg-log',
'skg-buffer', 'skg-keymaps-and-aliases').
** Some tests fake the handler map in a shorter shape
Several Emacs tests build 'skg-response-handler-map' with entries
shaped '(TYPE . HANDLER)', not the real '(TYPE HANDLER . ONE-SHOT-P)'
('test-skg-delete-from-confirmation.el',
'test-skg-strandeds-confirmation.el'). Code those tests reach must
keep removing entries by presence ('assoc-delete-all' and an 'assoc'
check), not through 'skg--unregister-response-handlers', which reads
the flag and signals on the short shape.
* Done
** 'skg--unregister-response-handlers' moved to 'skg-state.el'
It sat in 'skg-request-rerender-all-views.el'; it now sits beside
'skg-register-response-handler', and the absent-reference cleanup,
the text search and the rerender's overPrivateText confirmation use
it instead of their own loops.
** A save's alternative terminal messages share one ending
'skg--end-save-without-save-result' and the list
'skg--save-response-types-not-one-shot' ('elisp/skg-request-save.el')
replace six copies of the same handler-removal code.
** The save's confirmation handlers have their own file
'elisp/skg-request-save/skg-save-confirmations.el' holds the fork,
delete-from, strandeds, telescope-hoist and text-release handlers and
the fork confirmation buffer's commands. 'skg-request-save' requires
it; it reaches back only through 'declare-function', so there is no
require cycle.
** overPrivateText confirmations share a prompt and a registration
'skg--when-overPrivateText-approved' and
'skg--register-overPrivateText-confirmation-instead-of'
('elisp/skg-length-prefix.el'), used by the export to org, the
single-root content view and the readable-ids title lookup.
** Second pass: the relRepo helpers live with 'skg-set-relRepo'
They moved from 'skg-metadata.el' to 'skg-request-relRepo-info.el',
which now holds what its Neovim twin 'relRepo_info.lua' holds.
** Second pass: every removal of the overPrivateText handler is shared
The six hand-written 'assoc-delete-all' removals of
'overPrivateText-telescope-confirmation' call
'skg--unregister-response-handlers'.
** Second pass: the report buffers have their own file
'skg-messages.el' holds 'skg-big-nonfatal-message',
'skg-errors-and-warnings-to-org-string', 'skg--message-list-nonempty-p'
and 'skg-report-mode'; ten files that required the save only for them
require it instead.
** Second pass: restore requests and change facts have their own files
'skg-restore-requests.el' (the two restore commands, where a restoreRel
may stand) and 'skg-change-facts.el' (the '(diff ...)' facts, a
folder's change) left 'skg-metadata.el', matching their Neovim twins.
The folder atoms and 'skg--relationship-removed-p' stay in
'skg-metadata.el', which the pending detachment there needs.
** Second pass: redrawing a whole view has its own file
'skg-redraw-whole-view.el' holds 'skg--apply-streamed-view-update',
'skg-replace-buffer-with-new-content', the fold-atom and point-position
helpers, the twin of 'redraw_whole_view.lua'. 'skg-request-save.el' is
down to about 540 lines: the request, its envelope, the stream
handlers and the saved buffer's redraw choice.
** Second pass: every file has an Emacs-style header
Line 1 is ';;; FILE.el --- SUMMARY' with the lexical-binding cookie;
then ';;; Commentary:' (what it is for in a user's words, its entry
points and keys, what it leaves to which file) and ';;; Code:'.
'skg-init.el', the file a newcomer reads first, lists every file with
a phrase, grouped by what a user does. 'module-headers.org' records
the convention.

** Small hidden dependencies and dead code
'skg-sexpr-search.el' calls 'cl-some' without requiring 'cl-lib'
(it works because 'skg-compare-sexpr' loads it). 'skg-visit-link'
('skg-id-search.el') has no caller and no key; 'skg-sexp-at-or-after-point'
only tests call. 'elisp/abandoned/' is loaded by nothing and its
minor mode is broken; 'bash/compile-elisp.sh' skips 'abandoned/' but

'skg-visit-link' is a command a user could call by M-x, so it waits
for Jeff.
** Two small twin mismatches

'skg--ghost-sexp-p' sits in 'skg-metadata.el' (its
'skg--vognode-sexp-p' needs it), its twin in 'restore_requests.lua';

** Byte-compiler warnings that hide new ones
'bash/compile-elisp.sh' prints a dozen: magit functions not known to
be defined and unknown slots ('skg-request-file-path.el'),
'shell-mode-map' free ('skg-keymaps-and-aliases.el'), an unused 'index'
('skg-redraw-whole-view.el', in 'skg--content-with-fold-atoms').
'declare-function', a 'defvar' and renaming 'index' to '_index' would
silence them, so a new warning stands out. Safe; small. Do not touch
'skg-keymaps-and-aliases.el' beyond a 'defvar': 'skg-reload' keeps it.
** 'skg-metadata.el' (about 960 lines) still mixes concerns
Detach and attach, home-skgrepo moves, the merge request, the pending
detachment, metadata predicates and readers, metadata rewriting (edit
requests placed by rank) and headline-line text helpers. Its Neovim
twin 'metadata.lua' holds the same mix, so a split here should split
both clients alike, or the naming rule breaks. Moderate value.
