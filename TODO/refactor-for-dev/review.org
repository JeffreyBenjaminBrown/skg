** found
*** The rerun loop counts a clean shutdown as a failed start, and gives up after five
The rerun loop is 'bash/run-skg-rerunning-on-exit.sh', lines 52 and
58. Commit 817a97535 meant to change behaviour, so it is not a
refactor. Before, the loop reran the server forever, pausing at most
a minute. Now it exits with status 1 after five runs in a row that
each end within 30 s. It counts a run as quick whatever its exit
status, so a 'shutdown' request or a kill by PID counts the same as
a crash. Two cases show the difference. First, a server shut down or
killed five times, each within 30 s of its start: before, the loop
reran it each time; now 'start-servers.sh' exits and prints "ERROR:
skg kept failing to start" though nothing failed. Second, with
'--hot-reload', a server that cannot start because its port is held:
before, it came back within a minute of the port being freed; now it
stays down until the next edit under 'server/'. Sure of how it works;
medium sure it matters.
*** The AI client no longer runs under 'python3 -I' or from a lone copy
Line 88 of 'tools/skg-for-ai/skg_for_ai.py' now opens with 'from
server_connection import ...'. It changed in the split into modules,
598fa8c66 to 7b26bba0c. Before, the script was one file that used
only the standard library, so it ran however it was started. Now it
needs its own folder on 'sys.path'. Under 'python3 -I' (which implies
'-P') or with 'PYTHONSAFEPATH=1', or when 'skg_for_ai.py' is copied
alone to another folder, it stops at once with "ModuleNotFoundError:
No module named 'server_connection'". A reviewer reproduced this on
scratch copies. Nothing in the repo runs it so, but agents are often
told to run Python with '-I'. Sure it happens; little sure it matters.
*** One log warning's target changed module, which only the JSON log shows
The warning is "Failed to compute diff for repo", now at line 37 of
'server/git_ops/diff.rs'. Commit 6f5c4af38 moved it there from
'server/serve/handlers/save_buffer.rs'. Its tracing target is the
module that holds it, so it went from 'skg::serve::handlers::save_buffer'
to 'skg::git_ops::diff'. The terminal and 'server-to-user.log' leave
targets out, but 'server.jsonl' records them; Jeff's config turns it
on with 'timing_log = true'. A 'RUST_LOG' that names the old module
no longer reaches the warning. Nothing reads the field
('generate_report.py' does not). No other moved Rust code holds a
tracing call. Sure; trivial.
*** The test summary's Emacs and Neovim FAIL lines gain a space
Line 338 of 'bash/all-tests.sh' now pads with "printf '%-14s'" and a
space, since commit 7a21540ac. On a failed run, the terminal summary's
"Emacs tests" and "Neovim tests" FAIL lines now have one more space
before "(see"; 'ALL.org' is the same byte for byte. The commit's
message says so. Sure; cosmetic.
*** The handler-removal helpers rely on every type they name being one-shot
This is fragile, not wrong today. The helpers are
'skg--unregister-response-handlers' in Emacs and
'unregister_response_handlers' in Neovim, from 4758bb8da and
13a4f805e; the save endings and the overPrivateText retries were
built on them. The old copies lowered the pending-request count for
any handler they removed. The new ones lower it only for a handler
registered one-shot. Every type they are given today is one-shot, so
nothing changes. If a type is ever registered otherwise, the count
will stay high and the next request may hang. Sure it is not a bug
today.
