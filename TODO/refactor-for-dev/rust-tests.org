* Refactoring the Rust tests for the next agent
  The territory: the Rust test code under 'tests/' (the files the
  grouped binaries 'tests/grouped_*.rs' and 'tests/new.rs' declare,
  the unit tests in 'tests/unit/' that server modules include by
  '#[path]', and 'tests/shared/*.rs'), plus 'server/test_utils.rs'
  and 'server/test_utils/'. Not the fixtures, the shell integration
  tests, nor the harness scripts ('tests-harness-and-bash.org' covers
  those). What a test checks, a fixture's content, and which tests
  run are not yours.
  To find the most-copied blocks, measure: a script that slides a
  window of four stripped lines over every '.rs' under 'tests/' and
  counts repeats ranks them in a second; so does grouping local
  helper functions by their whitespace-stripped bodies. A test that
  calls a helper from 'server/test_utils.rs' imports it as
  'skg::test_utils::NAME' (or 'crate::test_utils::NAME' from
  'tests/unit/', which compiles inside the server crate); a helper in
  'tests/shared/' is visible only in the grouped binaries that
  declare its module.
