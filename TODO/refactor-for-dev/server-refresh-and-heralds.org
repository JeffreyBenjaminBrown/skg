* Refactoring for dev: 'server/refresh/', the heralds, the rerender pass
  The territory: everything under 'server/refresh/', plus the
  top-level files of 'server/' that draw views and compute heralds:
  'server/heralds.rs', 'server/herald_descriptions.rs',
  'server/herald_tokens.rs' and 'server/rerender_pass.rs'. The focused
  tests for it are 'bash/nextest.sh --lib --test grouped_views --test
  grouped_forks --test grouped_unit' (about forty seconds warm); add
  '--test grouped_saves --test grouped_repos' when touching
  'server/rerender_pass.rs'.

  The territory was already well factored: the refresh's rungs are
  short functions, each with a comment that 'docs/' cites by file. So
  most of the remaining candidates below are moves that would leave
  those citations stale.
* Done
** The viewnode stats pass carries its inputs in one 'ViewnodestatsPass'
   'set_viewnodestats_recursive' took eleven arguments and
   'set_herald_strings_in_viewnode' twelve ('server/refresh/viewnodestats.rs');
   the eight pass-wide ones are now one struct.
** 'relationship_member_stands_for' names the relationship 'set_relRepo' compares
   The (recorder, relation, target) that a member position represents
   was worked out inline in the 69-line 'set_relRepo'.
** A save's rerender carries the saved view as one 'SavedView'
   'update_views_after_save' ('server/rerender_pass.rs') handed four
   values separately to 'withhold_save_rerender' (ten arguments) and
   'register_saved_view' (eight); its two text-release gates now both
   ask 'save_rerender_release'.
** 'record_of_relationship_is_visible' is the one relRepo gate of the viewnode stats
   'flag_ancestor_relations' and 'relationship_is_visible' each spelled
   it out.
** An obsolete problem entry went to 'TODO/DONE/problems.org'
   "New relationship folders are populated before their completion
   visit" named 'server/to_org/', which the refresh rewrite deleted;
   'add_folders' now adds folders empty.
** Mirror substitution, a refresh rung, has its own file
   'server/refresh/substitution.rs' holds the seventh rung
   ('substitute_mirrors', 'substitute_roots' and their helpers), moved
   unchanged out of 'visit.rs'; the visit's helpers it calls became
   'pub(super)'.
** The claims, a refresh rung, have their own file
   'server/refresh/claims.rs' holds the fourth rung ('mark_claims',
   'claim_forks_folder_members_as_the_graph_does', what leaves a
   write-protected folder, and 'vanish'). 'visit.rs' is now 953 lines,
   and its comment banners say where the two rungs went.
** The herald table's conformance checks live in 'server/herald_conformance.rs'
   The vocabulary the server emits ('emittable_metadata_atoms') and the
   checks of the table and 'shared/herald-styles.json' left 'heralds.rs'
   (now 865 lines: the table, its serialization, the table queries).
   'property_and_change_kind_atoms' stayed: the table itself needs it.
** How to change a doc that cites a moved function
   The notes behind 'docs/' are plain '.skg' files in 'skg-system/'.
   For a one-line citation, editing the note's text directly, then
   'bash/export-docs.sh' and 'bash/check-docs-exported.sh', needs no
   server ('rg' the old path in 'skg-system/' to find the notes).
* Candidates left, best first
** Split more rungs off 'server/refresh/visit.rs' (953 lines)
   Requests ("8. requests", about 160 lines, 'fulfill_view_requests'
   on) and reinstate ("5. reinstate", about 230 lines with
   'after_drawing' and the containers-folder functions) are the next
   seams. Each is a mechanical move, but 'docs/mirrors.org' links
   'fulfill_view_requests' to 'visit.rs', and 'docs/glossary.org'
   cites 'after_drawing', 'add_containers_folder_under_member' and
   'folder_goes_when_empty' there; change those notes in the same
   commit. The rungs call back into 'visit.rs' helpers
   ('children_of', 'draw_item', 'folders_of_relation'), so expect a few
   more 'pub(super)'.
** One setter for an occurrence's view stats in 'viewnodestats.rs'
   Six setters end with the same three lines, 'if let Occurrence (t)
   = &mut tree . get_mut (treeid) ... { t . viewStats . X = Y; }'.
   A helper taking a closure would make each one line. ego_tree 0.11
   has no 'NodeMut::into_value', so a helper cannot return the
   '&mut ViewnodeStats'. Safe; small gain.
** PARTNER_ROLE_VOCAB's glyph column and 'RelationRole::glyph()'
   'TODO/problems.org' calls these vestigial: only a self-consistency
   test reads 'glyph()'. They are in 'server/dbs/in_rust_graph/relation_accessors.rs',
   outside this territory, and deleting the test would need the
   coordinator's word.
** 'update_views_after_save' still takes twelve arguments
   Its caller ('server/serve/handlers/save_buffer.rs', outside the
   territory) could build the 'SavedView' itself, and the restriction,
   environment and runtime could travel as one value. That changes a
   handler's code; worth it only alongside other work there.
** 'sentences_for_path' in 'server/herald_descriptions.rs' (128 lines)
   One match from metadata path to sentence, mostly literal text. It is
   long but flat; splitting it would scatter what a reader wants in one
   place. Leave it.
