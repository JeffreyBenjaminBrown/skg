* Refactoring 'tools/skg-for-ai/' for the next agent
  The territory: 'skg_for_ai.py' (the entry, with 'main' and an index
  of the modules) and the modules beside it (about 7000 lines), its
  suite 'test_skg_for_ai.py' with its groups in 'tests/', its fixtures, and 'README.org'. The
  tool's command line, everything it prints, the files it writes and
  the README are read by other agents as their manual: they must stay
  byte-identical (the README may be corrected where it is false).
  The suite needs 'target/debug/skg' in the worktree. Run it on a port
  of your own ('SKG_FOR_AI_TEST_PORT=18793'; it also takes that port
  plus one), since other worktrees may run it on the default 1793.
  It takes about 75 seconds; given group names ('python3
  tools/skg-for-ai/test_skg_for_ai.py daemon_checks'), it runs only
  those, in seconds.

** 'skg_for_ai.py' is split into modules, one concern each
   'skg_for_ai.py' keeps 'main' and an index of the modules: which
   module holds each command, and what lies below the commands. Each
   module beside it says in its first lines what it holds, and
   imports from the others by name: 'command_line' (the arguments
   and 'run_command'); the commands, in 'view_commands', 'save',
   'diff_and_commit', 'receipts', 'request_commands',
   'headline_commands' and 'daemon' ('daemon_client' is how a command
   reaches one); below them 'edited_compact_view', 'views',
   'compact_view', 'full_view', 'server_connection' and 'sexp'. No
   import cycle: each module imports only from those below it.
   The code moved unchanged, one module per commit, but for one
   adaptation: 'RUNNING_DAEMON' lives in 'server_connection' (with
   'connect_to_server', which reads it), and the daemon, which sets
   it, and 'command_commit', which reads it, name it
   'server_connection . RUNNING_DAEMON'. A moved function that read
   a mutable global of another module would read a stale copy; this
   is the only global any code rebinds ('global' appears nowhere
   else). The tests read the tool's names from their modules
   ('sexp . parse_sexp', ...).
   A few helpers moved down to the module that first needs them:
   'metadata_form' to 'sexp'; 'first_number' and
   'ancestor_generations' to 'full_view'; 'count_phrase',
   'is_editable_node' and 'reads_claims' to 'compact_view'; the
   overPrivateText helpers and 'response_text_field' to
   'server_connection'; 'release_withheld_save_rerender' and the
   sidecar helpers to 'views'; 'NEW_NODE_HANDLE_WORD',
   'described_handle' and 'descendant_indices' to
   'edited_compact_view'.
   Running the tool now writes '__pycache__/' beside it (gitignored);
   no module may import 'skg_for_ai', which runs as '__main__' and
   would be loaded a second time.
** The suite's checks are in 'tests/', a module per group
   'test_skg_for_ai.py' (4206 lines) is now the entry: its docstring
   with an index of the groups, 'main', and 'SCRATCH_SERVER_GROUPS'.
   Each group is a module in 'tests/' ('no_server_checks',
   'reading_checks', 'writing_checks', 'placing_and_forking_checks',
   'more_words_checks', 'reviewing_checks', 'daemon_checks',
   'two_owned_skgrepos_checks', 'perspective_checks',
   'receipts_checks'), and 'tests/harness.py' holds what they share
   (paths and port, scratch servers, 'run_tool', the 'require_*'
   checks, the diff view's files, daemons). No group imports another.
   The statements moved unchanged; a profiler over every 'check_*' and
   'failures_*' call showed the same 138 calls in the same order. The
   names end in '_checks' because 'daemon', 'receipts' and 'save' are
   the tool's own module names. The commands are unchanged; group
   names on the command line run only those groups.

** How the splits were made
   A script ('move_section.py', not kept; easy to rebuild) took line
   ranges of a module, wrote them unchanged into a new one, generated
   its imports from the names it uses (refusing a cycle), pruned the
   source's imports, and pointed the other modules' 'from SOURCE
   import' lines at the new module; qualified uses in the tests
   ('compact_view . herald_text') it listed, to fix by hand.

   says which keys a case may use. A small class per group, or one
   with optional fields, would name them. Test-only, so safe; the
   keys are read in about 90 places, an hour or two.
