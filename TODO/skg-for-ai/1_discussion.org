#+title: Making Skg readable and editable for AI agents

* Why
Jeff wants to edit Skg data with an agent's help. The first case: merge the
good parts of an old document (the 'public' copy of OVERVIEW) into the new
one (the 'skg' copy, created by importing docs/). Today an agent can only
read and write Skg through the TCP protocol or by editing raw .skg files,
and neither is pleasant or safe for real work.

* What an agent sees today
A content view is Org text whose every headline carries metadata:
: * (skg (node (id 6f1c...) (source skg) (affectsParent na))) foundation : org-mode
Real views add relationship and fold data, and IDs are 36-character UUIDs,
so most of a view's characters are metadata. Heralds compress this for
humans, in the clients only; the server sends the raw metadata.

* Jeff's proposal: 'skg-for-ai' views
** The idea
Render an ordinary content view, then derive a compact view in which each
headline's metadata is replaced by a pointer to the corresponding line of
the full view. An agent reads the compact view, and looks up a line's
metadata only when it needs it.
** Claude's assessment
Reading this way is cheap and clearly worthwhile. The hard part is editing:
the server saves a view only as a full buffer, metadata included, so edits
made in a compact view must be mapped back onto the full one before saving.
*** A possible editing loop
1. Render the full view through the server, and keep it.
2. Derive the compact view, each headline tagged with a short handle.
3. The agent edits the compact view.
4. A tool rebuilds the full buffer: each tagged headline gets its original
   metadata back; an untagged headline is a new node, which Skg creates
   from a bare headline.
5. Save through the server, as a client would. The save reply re-renders
   the view, which closes the loop.
*** Risks in that loop
**** Moved or deleted headlines
In Skg, deleting a headline from a view removes it from its container; it
does not delete the node (that takes an explicit deletion marker). A tool
that silently drops a missing handle's metadata could therefore change the
graph in ways the agent did not intend. The rebuild step should report every
structural change before saving.
**** Stale views
If the data changes between rendering and saving, the save must fail
rather than overwrite. Clients rely on the server's existing checks; the
tool should too, and never write .skg files directly.
