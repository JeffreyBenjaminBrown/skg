** Words this plan uses
- An occurrence of a graphnode is a viewnode that stands for it (an
  unrestricted vognode). A buffer has at most one editable occurrence
  of a node; the others are write-protected, and the server draws
  nothing under a write-protected one. A member is a child viewnode
  whose 'affectsParent' is true; a non-member has it false.
- A partner folder is a child of an occurrence that lists the node's
  partners in one relation: the subscribee, overridden, hidden,
  subscriber, overrider, hider, container, mentioner, acquired and
  acquired-by folders ('PartnerFolder' in 'server/types/viewnode.rs').
  The subscribee and overridden folders are editable sets
  ('FolderPolicy::EditableSet': the user edits the relation by editing
  the folder); the others are write-protected sets the server
  generates. An absent folder expresses no opinion; a present one is
  the folder's full set.
- The write-protected-occurrence check is
  'errors_for_writeProtected_occurrences'
  ('server/from_text/write_protected_edits.rs'), run by the save on
  every buffer. Today it refuses a save when a write-protected
  occurrence's title or home skgrepo differs from the graph, when a
  present alias folder or flags folder under it differs, or when it
  holds a member child; it does not look at partner folders.
- The folder reconciler ('reconcile_partnerFolder_children',
  'server/update_buffer/reconcile/partner_folder.rs') computes, for a
  folder under a node (the recorder), the members the folder should
  hold from the live graph: outbound relations through
  'outbound_rel_partners_for_relation_gated', inbound ones through
  'other_member_pids_gated', each extra ID resolved to its node's pid
  ('pid_of'), and the members a skgrepo restriction hides omitted
  ('omit_restricted_members'). In a TDV buffer it draws instead from
  the straddle, the union of both graphs, and a member whose
  relationship exists only in the before-graph is drawn with the
  presence fact '(diff rel-)'; a node that exists only in the
  before-graph is drawn as a historical phantom, not an unrestricted
  vognode.
- 'ViewForest::nodes' ('server/types/tree/forest.rs') iterates every
  viewnode of a buffer. It chains each root with the root's
  descendants, and ego-tree's 'descendants' begins with the node
  itself, so each root comes out twice.

* Agreed behavior
** A present partner folder under a write-protected occurrence must equal the graph
For every write-protected occurrence of a saved buffer, every partner
folder present under it lists exactly the node's partners in that
relation as the graph has them, compared as a set of node IDs, or the
save is refused as an edit to a write-protected occurrence, naming
the node and the folder. An absent folder expresses no opinion. This
holds in every view, as the rest of the check does; it restores what
the comparison with the last rendering refused before the previous
plan replaced it.

The expected set is computed by one function, shared with the folder
reconciler: what the reconciler now computes inline for the live
graph is lifted into a function that takes the graph, the recorder,
the folder kind and the skgrepo restriction, and both the reconciler
and the validator call it, the validator with the save's restriction.
The validator never re-derives a folder's members by itself.

The members the validator compares are the folder's unrestricted
vognode children with 'affectsParent' true that carry no
removed-relationship presence fact ('(diff rel-)'), plus its Unknown
phantom children by their raw ID, as the reconciler matches them.
Non-member children, historical phantoms and members marked removed
are not counted, so a TDV buffer that shows a removed partner under a
write-protected occurrence is not refused for showing it.
** Every viewnode is yielded once
'ViewForest::nodes' yields each viewnode of the buffer exactly once,
roots included. Callers that counted on nothing keep working; a
caller that reported or counted a root twice stops doing so.

** DONE Slice 0: partner folders join the write-protected-occurrence check
First, in 'reconcile_partnerFolder_children', lift the live-graph goal
computation (from 'raw_outbound_members' through 'graph_members',
including 'omit_restricted_members') into a function in the same
module, 'partnerFolder_members_in_graph (graph_snap, runtime,
recorder_pid, kind, skgrepo_restriction) -> Vec<ID>', and call it from
the reconciler; the suites must pass unchanged after this step alone.
Then, in 'errors_for_writeProtected_occurrences', which gains the
save's 'skgrepo_restriction' from its caller in 'server/from_text.rs':
for each write-protected occurrence, for each partner folder present
among its children whose kind has a relation member role, read the
folder's members as the behavior section defines them (members with
no removed-relationship presence fact, plus Unknown phantoms by raw
ID), call 'partnerFolder_members_in_graph' with the same restriction,
compare as sets, and on a difference push 'EditedWriteProtectedOccurrence'
with the change named ("changed subscriptions", "changed overrides",
"changed containers", and so on, one phrase per folder kind). A
folder member carrying a relRepo request counts as a difference, as
an alias does. The hidden-in and hidden-outside subscribee folders
have no relation member role and are not checked. Docs: the sentence
in 'docs/api-and-formats.org' and the glossary's "editable,
write-protected" entry that list what a save refuses under a
write-protected occurrence name the partner folders too. Tests, in
'tests/new/buffer_to_viewnodes/validate_tree.rs' or beside the
function: a subscribee folder with an extra member under a
write-protected occurrence is refused, in a content view and in a
TDV buffer; one that matches passes; an absent folder passes; a
container folder (a write-protected set) that differs is refused the
same way; under a skgrepo restriction, a folder drawn without the
hidden members passes; and in 'tests/pcsvf/', a TDV buffer whose
write-protected occurrence shows a removed partner with '(diff
rel-)' saves unchanged.
