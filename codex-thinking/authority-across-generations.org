* Authority after another publication
** Observation
'server/serve/handlers/save_buffer.rs::validate_save_authority' currently
requires the client's graph generation to equal the current graph generation.
That safely refuses stale bases, but also refuses an unaffected G1 buffer
after an unrelated G2 save. The plan explicitly requires independent release.
** Question to resolve
What exact retained read set proves an old view's save remains valid against
current graph/source interpretation, including negative lookups and implicit
neighbor effects? A set of visible normal PIDs alone may omit dependencies.
** Candidate approaches
Retain each view's immutable base snapshot and compare all semantic inputs
used by save planning; or derive a validated dependency fingerprint while
constructing/planning the view. Neither should silently grant current authority
by changing a counter. Existing client buffer text/tick/token must still match.
** Next bounded investigation
Trace save planning's dependency reads and existing collateral/dependency
tracking before choosing the proof. Keep current refusal until the proof is
implemented and tested. This is an implementation question within the accepted
contract, not a request to reopen its architecture.
** Rejected shortcuts
Comparing only authored/visible IDs misses newly added inbound overrides and
delete-propagation referencers: see [[file:save-dependency-audit.org][the dependency audit]].
Comparing complete scalar nodes for every accepted headline may reject even
a safe indefinitive conversion: an ancestor title change need not be an input
to the descendant's save. A blanket connected-component closure could likewise
make unrelated branches conflict through one shared ancestor.
Tracing every graph read would avoid a manual inventory, but the graph exposes
its maps publicly and many algorithms read them directly. Retrofitting only
'get' and 'pid_of' would leave untracked reads while appearing comprehensive.
** Hypothesis to audit before implementation
Retain each view's exact accepted graph+manifest and config/source-set identity.
Plan against current semantics; identity/revision/token/read-only gates run
before any confirmation. Before effects, compare complete node facts for all
actual final Save/Delete IDs, including merge/fork/Hoist/collateral outputs.
Compare every configured source path's digest-or-absence for those PIDs.
For accepted/authored forest IDs and final instruction IDs, compare explicit
PID resolution and structural inputs (home, extra IDs, sourced relationships,
aliases, properties), without making unmodified indefinite headline scalars
an unconditional dependency. Include direct inverse sets (including negative
facts), subscription members/home facts, and transitive override chains from
both base/current graphs. Current invariants still run before the batch.
The open question is the exact expansion and which scalar facts outside the
final write set can alter meaning or authorize collateral writes. The next
audit must produce a counterexample or a bounded precise closure; no grant
should depend on the present sketch.
** Resource-lifetime follow-up
The first retained-base adapter keeps an 'Arc<SelectedStoreState>', which also
holds a Tantivy Searcher. Pending application environments retain it too.
The proof needs graph/manifest/config facts after rendering; retaining an old
Searcher throughout editor waits conflicts with the plan's bounded query-work
lifetime. Split the retained semantic proof data from query resources before
claiming that boundary complete. Avoid copying a corpus-sized manifest for
each buffer when making that split.

** Concrete resource split
Keep the published pair intact for actual query leases. Give retained view
proofs a separate graph-base value containing shared graph/manifest pointers
and their identities. Share the manifest in the publication itself so making
a proof does not clone all corpus paths per buffer. Pending application and
enrichment payloads retain this proof, not an environment.

Collateral batches also wait for client authorization, so merely removing
the pending-offer environment is insufficient. Their renderer reads graph
and config only. Change its context to those explicit inputs; then the whole
retained batch can be free of Searchers, including while awaiting approval.
The existing foreground adapters can keep accepting an environment and
extract those same inputs. Verify publication pointers may be released while
proofs remain, and rerun real base-ACK, source-switch and rendering coverage.

** Verification and next retention boundary
The view proof, collateral batch/offer, and enrichment payload split passes
53 focused tests, 22 source-set tests and five grouped view tests. The pending
application test observes the old publication being dropped while its shared
graph/manifest facts survive. Initial compile attempts exposed the expected
manifest type changes and one missed fixture import; their logs are retained.

The separate incident snapshot map still retains complete runtime pairs
through report work. Migrate it to semantic snapshots next, alongside durable
query execution: report rendering needs no Searcher, while a ready query can
create a bounded matching reader from retained or reconstructed incident
evidence. Do not claim all historical index resources are released yet.
