#+title: Claude to Claude: unify the skills across skg workspaces

* What this is
A one-time task for the Claude agent in each skg workspace (skg, skg2, skg3).
Jeff runs each workspace as an independent clone in its own container, so
each agent has accumulated its own Claude skills. They should become one set.
Delete this file once every workspace has done the task below.

* Where skills live now
** Skills about skg go in this repo, at '.claude/skills/'
Claude Code reads project skills from '.claude/skills/'. Of '.claude/', only
'skills/' is tracked (see '.gitignore'); everything else there is Claude
state, including credentials, and must never be committed.

The first such skill is 'verify': it drives an isolated skg server over TCP.
It was rewritten on 2026-10-03 to match the current code (no TypeDB,
ownership by folder, an import mode, safe cleanup), and its recipe was run
end to end.
** Skills useful in any project go in 'my-dot-claude/skills/'
'my-dot-claude/' is the user-level Claude config ('CLAUDE_CONFIG_DIR') that
every project shares, including non-skg projects such as midi.
** Why skg-specific skills are not in 'my-dot-claude/'
*** They describe the code, so they should change with it
The 'verify' skill went stale (its config example used keys the server now
rejects) because it was versioned nowhere. In this repo, the commit that
changes a config format or protocol can fix the skill in the same commit,
and every branch carries the matching version.
*** The workspaces already share commits through GitHub
So unifying skills is an ordinary merge. 'my-dot-claude/' syncs only when
Jeff pushes and pulls it on the host: its remote is SSH, and the containers
have no SSH.
*** Other projects stay uncluttered
A skill for driving the skg server is noise in a midi session.

* What to do in your workspace, once
** Before pulling the commit that tracks '.claude/skills/'
If your workspace has its own untracked '.claude/skills/verify/', Git will
refuse to pull, since the pull would overwrite untracked files. Move your
'.claude/skills/' aside (somewhere outside the repo, or under a name Git
ignores), pull, then continue.
** Sort each of your skills
*** A skill about skg
Compare it with the tracked one of the same name, if any. Merge anything
yours knows that the tracked one lacks, and check it against the current
code, which is authoritative. If there is no tracked counterpart, add yours
under '.claude/skills/'. Commit only as Jeff's commit rules allow.
*** A skill useful in any project
Move it to 'my-dot-claude/skills/'. That repo tracks only an explicit list
of files (its '.gitignore' ignores '*' and then re-includes some), so the
first workspace to add a skill there must add '!skills/' and '!skills/**'
to that list, and keep '__pycache__' and the like ignored. It should also
add 'skills/' to the "What's tracked" section of that repo's 'README.md',
saying that it holds only skills useful in any project: a skill about one
project belongs in that project's '.claude/skills/', versioned with the code
it describes.
Then ask Jeff to push it from the host, and the other workspaces to pull it
there.
** Leave one copy of each skill
After moving a skill, delete the copy you moved it from. Two skills with
the same name, one per level, would leave which one runs unclear.
** Report to Jeff
Say which skills you merged, added, or moved, and anything you were unsure
how to classify.
