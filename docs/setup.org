* Setting up Skg
Everything runs locally on your machine. You don't have to share.
Skg is free software, without a ghost of a path to making money.

This is just enough for a programmer to see how to get it working.
Please ask an AI for help setting it up.
** build the Docker container
See the image and mounts documented in =../bash/docker.sh=.
** start the Docker container
See ../bash/docker.sh
** within the Docker container
*** start the Skg server
See ../bash/start-servers.sh
It validates the config first, and refuses to start on an invalid one.
A config key the server does not know (a misspelling, or an old
spelling such as =max_role_tree_depth= for =max_roleTree_depth=) does
not stop it: the script prints a warning naming the key, and once the
client connects, it shows the same warnings in a buffer
(=*SKG Server Warnings*= in Emacs, =skg://messages/server-warnings=
in Neovim).

It takes two options, both off by default:
#+begin_example
   ../bash/start-servers.sh [--deb] [--hot-reload]
#+end_example
- Without =--deb= it builds and runs the release profile
  (=target/release/skg=), which is fast. The first release build
  takes minutes, during which the script sits at "Validating config";
  that is not a hang. With =--deb= it builds and runs the debug
  profile (=target/debug/skg=), slower to run but quicker to rebuild.
  (The environment variable that used to select release is gone;
  release is now the default.)
- Without =--hot-reload= nothing watches the server's source: the
  server runs, and comes back if it exits or is killed, but an edit
  under =server/= takes effect only when you run the script again.
  With =--hot-reload=, cargo-watch rebuilds and restarts the server
  on every edit under =server/=, which is for working on the server.

Before starting the server, the script byte-compiles the Emacs client
(=../bash/compile-elisp.sh=), writing a =.elc= file beside each =.el=
file under =elisp/=. An Emacs that loads the client from this tree
must be at least the container's version (31.1) for those =.elc=
files to load. A =.el= file newer than its =.elc= (one edited since
the last compile) is loaded as source, so a stale =.elc= does no
harm. If =emacs= is not on the path, or the compile fails, the
script says so and starts the server anyway.
*** optional : import data from org-roam
See [[file:COMMANDS.org::#import-org-roam][importing from Org-roam]] for arguments,
supported input, and setup steps. Use a fresh staging directory:
the command deletes existing '.skg' files in its destination.
For an additive, previewed import of mixed Markdown and ordinary Org files
into an existing owned skgrepo, use [[file:COMMANDS.org::#import-md-and-org][=M-x skg-import-md-and-org=]]
after starting the server and client instead. Keep the source documents as
a backup; Org export is readable but not a round trip.
** set up your data folder
You can make your thoughts entirely private, entirely public,
or a mix, and you can share with anyone.
See example-data/ for how.

Keep each person's skgrepos in a folder of their own under the data
root ('data/AUTHOR/REPO'). In 'skgconfig.toml', every skgrepo is
yours unless its entry says 'foreign = true'. List yours most public
first: their order is your privacy ladder. The foreign ones have no
place on it and may be listed anywhere. A config which sets
'owned_folder' or relies on the 'owned/' folder is converted by
'bash/migrate-to-foreign-flag.sh CONFIG [NEW_FOLDER]'; see
'api-and-formats.org', "Skgrepos".

Two people (or a person and an AI teammate) can share one data tree,
each running a server from a config of their own: both configs list
the same skgrepos, each marks the other's 'foreign = true', and each
gives its server its own 'port' and its own 'tantivy_folder', so the
two never share a search index. 'data/skgconfig-ed.toml',
beside 'data/skgconfig-jeff.toml', is such a config. Each server
watches every skgrepo directory and reloads the '.skg' files that
change on disk, so it shows another server's saves, or a 'git pull',
within about a second ('repo_watch_quiet_ms'), and rerenders the open
views that show them. A changed config is the one thing that needs a
rebuild of the stores ('skg-rebuild-session-lifetime-stores' in
Emacs), which re-reads it, so a skgrepo added to it needs no restart.
** start the client
#+begin_src elisp
  (progn (load-file "../elisp/skg-reload.el")
         (skg-reload)
         (skg-client-init "../data/skgconfig.toml"))
#+end_src
** Now you can use it. See [[./COMMANDS.org][commands]].
** stop the server later if you want
#+begin_example
   ../bash/stop-servers.sh
#+end_example

You can't use the client (much) when the server isn't running.
