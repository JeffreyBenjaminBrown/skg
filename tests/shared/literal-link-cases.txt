# Which [[id:ID][LABEL]] links in Org body text are real links, and which
# are examples in text Org shows literally. One contract, three
# implementations, each tested against these cases:
#   Rust:   server/types/textlinks/org_literal_ranges.rs
#           (tests/textlinks.rs)
#   Emacs:  elisp/skg-link-annotations.el
#           (tests/elisp/test-skg-link-annotations.el)
#   Neovim: nvim/lua/skg/link_annotations.lua
#           (tests/nvim/link_annotations_spec.lua)
#
# Format: a case begins with a line '==== NAME', followed by its text,
# and ends with a line '---- live:' then the IDs of the real links, in
# order, separated by spaces. Lines before the first case are comments.
# Case text contains no headlines, since the clients (which see whole
# buffers) also end a block at a headline, and the server (which sees
# one body at a time) never meets one.

==== inline verbatim and code are literal
real [[id:a][A]] and =[[id:b][B]]= (~[[id:c][C]]~)
---- live: a
==== verbatim markers need Org's borders
x=[[id:d][D]]=y and = [[id:e][E]] = here
---- live: d e
==== fixed-width lines are literal, even indented
: [[id:f][F]]
  : [[id:g][G]]
:
not fixed-width:[[id:h][H]]
---- live: h

#+end_quote
