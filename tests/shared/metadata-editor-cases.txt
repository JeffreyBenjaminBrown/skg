# How each client's metadata editor (C-c v m, <localleader>vm) shows a
# headline's '(skg ...)' metadata, what it saves, where a command
# writing a request puts it, and how the buffer corrections are shown.
# One contract, two implementations, each tested against these cases:
#   Emacs:  elisp/skg-sexpr-edit.el, elisp/skg-sexpr/skg-metadata-fields.el,
#           elisp/skg-metadata.el, elisp/skg-request-server-warnings.el
#           (tests/elisp/test-skg-metadata-editor-cases.el)
#   Neovim: nvim/lua/skg/metadata_edit.lua,
#           nvim/lua/skg/sexpr/metadata_fields.lua,
#           nvim/lua/skg/readiness.lua, nvim/lua/skg/server_warnings.lua
#           (tests/nvim/metadata_editor_cases_spec.lua)
# Both read the fields and the order of the parts from
# shared/metadata-fields.json.
#
# Format: a case begins with a line '==== NAME'. Each of its fields is
# a line '---- KEY: VALUE', or a line '---- KEY:' followed by the
# lines of a block, which run to the next '---- ' or '==== ' line.
# Lines before the first case are comments.
#
# A case of the editor gives:
#   metadata: a headline's metadata as the server writes it, one kind
#     of headline the fields table knows per case or more (a buffer
#     root is never written, so it has none);
#   title (optional): the headline's title, which the editor shows,
#     read-only, above an occurrence's metadata;
#   fill-in (a block): what the editor shows, in order;
#   strip: what applying the editor sends back when nothing was
#     changed;
#   edit request and with the edit request (optional): the metadata
#     after a command makes REQUEST its edit request;
#   readiness request and with the readiness request (optional): the
#     metadata after a gesture makes REQUEST its readiness request.
# A case of the buffer corrections gives:
#   corrections: the (corrections ...) field of a save-result, for a
#     view no buffer shows;
#   display (a block): the org text appended to the server-warnings
#     buffer.
